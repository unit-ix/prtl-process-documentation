UNIT-IX · backend: azure

Vier Dienste, eine Anfrage, eine Grenze

Wie der Azure-Stack einer UNIT-IX-App heute aussieht — und was beim Klick eines Nutzers tatsächlich passiert. Vier Dienste tragen jede App; alles Weitere kommt erst dazu, wenn es gebraucht wird.

Der Stack

Vier Dienste sind unverzichtbar. Die Auswahl fällt nicht nach Preis, sondern nach je einer Eigenschaft, die die Alternativen nicht haben.

Über dem Strich: Pflicht. Darunter: optional — im Diagramm gestrichelt umrandet. Kein Key Vault, per Design — der App Service erreicht die Datenbank über seine Managed Identity, es gibt kein Secret zu verwahren.

Was bei einem Klick passiert

Sechs Schritte, zwei davon einmalig pro Sitzung. Die warme Zone links ist das Gerät des Nutzers — alles dort ist verhandelbar. Gestrichelt ist, was optional dazukommt: drei Dienste am App Service und ein zweiter Ausweis-Aussteller.

Die fünf Prüfungen am Token

Rund 45 Zeilen in apps/api/src/auth/verify.ts. Fällt eine durch, antwortet die API mit 401 und tut sonst nichts. Einzige Ausnahme: /health, damit Azure den Server prüfen kann.

  • Signatur — kommt der Ausweis von Microsoft?
  • iss — von unserem Mandanten?
  • aud — für unsere API?
  • exp — noch gültig?
  • scp — darf der Inhaber die API benutzen?
